# Cluster-First Inverted HNSW Routing Architecture

## 1. System Objective
Solve the graph fragmentation and traversal starvation of single-graph HNSW pre-filtering by clustering items based on overlapping metadata conditions *first*, then routing queries using an inverted cluster index.

---

## 2. Step 1: Offline Hierarchical Metadata Clustering
* **Objective:** Group items with overlapping categorical conditions (tags/rules) into natural density pockets.
* **Algorithm:** Agglomerative Hierarchical Clustering using **Jaccard Distance**.
* **Why Jaccard:** Measures dissimilarity over multi-valued/overlapping sets ($D_J = 1 - \frac{|A \cap B|}{|A \cup B|}$). Items with high attribute overlap are placed closer together in the dendrogram.
* **Output:** A tree of stable macro-clusters that capture categorical overlaps without combinatorial explosion.

---

## 3. Step 2: Cluster-Aware Inverted Indexing
* **Data Structure:** Build an inverted bitmap index (Roaring Bitmaps) mapping each **Cluster ID** to its member item IDs.
* **Metadata Layer:** Instead of indexing individual raw scalar fields separately at runtime, the metadata engine indexes the *macro-cluster IDs* generated by the hierarchical tree.

---

## 4. Step 3: Online Routing & HNSW Execution Plan
1. **Query Ingestion:** A user query arrives with strict rule constraints/tags.
2. **Cluster Matching:** The routing engine evaluates the query tags against the hierarchical cluster centroids to identify the relevant target **Cluster IDs**.
3. **Index Selection:** 
   * **If Broad Match (> 10% data):** Route the HNSW search exclusively into the sub-graph of the matching cluster(s) via bitset masking.
   * **If Narrow/Sparse Match (< 1% data):** Bypass HNSW entirely; pull the exact matching IDs via the inverted bitmap index and run a **SIMD-accelerated brute-force scan with a priority queue**. Can do in multithread in a thread pool of 4 - bucket like (for each 20 points) so that those can be calculated concurrently with SIMD.
